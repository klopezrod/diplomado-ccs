## 🤝 Colaboración y Flujo de Trabajo

Para mantener el repositorio organizado y garantizar un código estable, seguimos una metodología de trabajo estructurada mediante **Feature Branching**, **Issues** y **Pull Requests**:

1. **Issues (Gestión de Tareas):**
   * Toda mejora, corrección de bug o nueva funcionalidad se registra previamente en la pestaña de **Issues** de GitHub para mantener una discusión centralizada.

2. **Feature Branching (Ramas por Funcionalidad):**
   * No se trabaja ni se sube código directamente a la rama principal (`main` o `master`).
   * Para cada tarea o issue asignado, se crea una rama nueva a partir de `main` siguiendo esta convención de nombre:
     * `feature/nombre-de-la-funcionalidad` (para nuevas características)
     * `fix/descripcion-del-error` (para correcciones)
   ```bash
   git checkout main
   git pull origin main
   git checkout -b feature/nueva-seccion
